# Agent notes

## Where product changes go

**The phone app is `react-app/` (React Native / Expo) and nowhere else.** It serves both Android
and iOS from one codebase.

`archive/` is off limits:

- `archive/android-native-legacy/` — the superseded native Kotlin Android app (v1.x)
- `archive/ios-native-legacy/` — an unfinished native Swift iOS port

Neither is a Gradle module, neither is built by CI, and neither is shipped. Do not implement
features or bug fixes there. Use them as a behavioural reference when porting something, then
write the change in `react-app/`.

`wear/` is **not** archived — the Wear OS companion is still a live Kotlin Gradle module that is
built and released with the phone app, and it still takes changes.

## React app specifics

Read `react-app/AGENTS.md` before writing React code: Expo has changed and the versioned docs at
https://docs.expo.dev/versions/v57.0.0/ are the source of truth.

`react-app/android/` and `react-app/ios/` are regenerated by `npx expo prebuild`. Never hand-edit
them — every durable native change belongs in a config plugin under `react-app/plugins/`, or in
`react-app/app.json`.

The phone app version comes from `react-app/app.json` (`expo.version` and
`expo.android.versionCode`). There is no version in the root `gradle.properties`.

## Checks

- Typecheck and unit tests for the phone app: `cd react-app && npx tsc --noEmit` and
  `cd react-app && node --test --experimental-strip-types tests/*.test.ts`
- `react-app/tests/` uses `node:test`; add a test for behaviour worth pinning down.
